# 00 — Project Charter

## 1. الهدف

بناء مختبر سطح مكتب محلي يجعل الطالب يتعامل مع مقسم EWSD بصورة عملية بدل حفظ المخططات والأوامر فقط.

التجربة المطلوبة هي:

**MML command → validation → switch state change → SQLite → visual DLU/SYP update**

والعكس أيضًا:

**click on DLU/card/port → inspect state → perform controlled operation → observe MML-equivalent state**

## 2. حدود المشروع

### داخل النطاق

- Windows 11.
- تشغيل Offline.
- SQLite محلية.
- مقسم افتراضي مثل ALE1.
- DLU 10 وDLU 50 كبداية.
- Side 0 / Side 1.
- Shelves 0–7.
- Slots 0–15.
- SLMA 8/16-port.
- SLMA CMRL بستة منافذ.
- SLMD.
- بطاقات التحكم والتغذية المذكورة في المقرر.
- EQN/DN.
- CPT/SNNP.
- MML commands.
- Command Files.
- FSM وحالات act/standby/mbl.
- SYP alarms.
- call-path simulator.
- labs للمادة.

### خارج النطاق

- اتصال بمقسم EWSD حقيقي.
- التحكم بمعدات اتصالات فعلية.
- محاكاة إلكترونية/كهربائية دقيقة لمستويات الإشارة.
- SS7 stack حقيقي كامل.
- SIP/IMS production stack.
- أنظمة billing فعلية.
- تعدد المستخدمين أو خادم مركزي.
- محاكاة hardware timing على مستوى FPGA/PCM الفيزيائي.

الهدف هو **محاكاة تعليمية ذات مصداقية سلوكية** وليس استنساخ نظام Siemens مغلق المصدر.

## 3. مبادئ التصميم

### قاعدة واحدة للحقيقة

SQLite هي مصدر الحالة الدائم. لا توجد نسخة مخفية من المشتركين في React.

### Core مستقل

منطق المقرر لا يعتمد على React أو Tauri. يجب أن نستطيع تشغيل MML tests من Node/TypeScript بدون فتح الواجهة.

### أخطاء تعليمية دقيقة

كل خطأ يجب أن يشرح السبب:

- EQN غير صالح.
- Slot غير موجود.
- Card type غير مناسب.
- Port خارج السعة.
- DN مستخدم.
- EQN مشغول.
- diag قبل ost=mbl.
- مشترك محجوب يحاول مكالمة صادرة.
- CPT يرفض الوجهة.

### عدم اختراع سلوك غير مقرر

عند وجود تفصيل غير محسوم في المواد، يفضل النموذج الأكثر بساطة والقابل للتفسير في الامتحان، ويُوثق كقرار محاكاة.

## 4. معيار النجاح الأكاديمي

المشروع ناجح عندما يستطيع الطالب تنفيذ سيناريو كامل أمام الدكتور دون كتابة كود:

1. اختيار DLU وSlot.
2. تركيب/تأكيد بطاقة.
3. إنشاء مشترك عبر MML.
4. رؤية المنفذ يتحول إلى idle.
5. الاستعلام عنه.
6. تعديله أو حجبه.
7. رؤية أثر الحجب على المكالمات.
8. وضع الوحدة/البطاقة في mbl.
9. تنفيذ diag بعد تحقق الشرط.
10. تشغيل سيناريو Command File.
11. مشاهدة alarm وcall path يتغيران تلقائيًا.

## 5. قرار معماري مبكر

لن نبني واجهة جميلة ثم نربطها لاحقًا. نبدأ بالنواة والقيود؛ بعدها الواجهة تصبح renderer للحالة الصحيحة.

## 6. ترتيب البناء

**Foundation → Domain Core → SQLite → MML → DLU UI → SYP → Calls/CPT → Labs → Packaging → Final Audit**
